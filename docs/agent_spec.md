# Специфікація LLM-агента Domain Knowledge Hub (Результат 1)

## 1. Мета, користувачі, межі та рівні автономності
* Мета агента: інтерактивний пошук, агрегація та верифікація знань щодо фінансових рекомендацій в електронній комерції поверх гібридного сховища (RDF-граф, векторний пошук по документах, SQL OLAP-вітрина).
* Цільові користувачі: бізнес-аналітики фінтех-напряму, інженери рекомендаційних систем, спеціалісти з ризик-менеджменту.
* Рівень автономності: Level 2 (Read-only автономний пошук і синтез відповідей із цитатами; запис нових фактів вимагає перевірки SHACL та схвалення людини).

## 2. Інструменти агента (JSON-схеми, права, обмеження)
1. query_kg_sparql (read-only) - безпечні SELECT-запити до RDF-графа data/hub.ttl.
   - JSON-схема входу: {"type": "object", "properties": {"entity_keyword": {"type": "string", "maxLength": 64}}, "required": ["entity_keyword"]}
   - Обмеження: заборонено INSERT, DELETE, DROP, LOAD; таймаут 2.0 с.
2. search_docs_vector (read-only) - семантичний пошук фрагментів у корпусі data/docs.json.
   - JSON-схема входу: {"type": "object", "properties": {"query": {"type": "string", "maxLength": 120}, "top_k": {"type": "integer", "minimum": 1, "maximum": 5}}, "required": ["query"]}
   - Обмеження: повертає лише публічні метадані без персональних даних клієнтів (PII).
3. query_olap_sql (read-only) - агреговані вибірки по вітрині ефективності data/olap.db через параметризований семантичний шар.
   - JSON-схема входу: {"type": "object", "properties": {"product": {"type": "string", "maxLength": 64}}, "required": ["product"]}
   - Обмеження: виключно параметризований SELECT по таблиці sales_metrics; заборонено DDL/DML-операції.

## 3. Політики безпеки, ліміти та заборонені дії
* Ліміти виконання: максимум 5 кроків (max_steps = 5) на один запит, бюджет токенів <= 4096 токенів, загальний таймаут 15 секунд.
* Заборонені дії: прямий запис або видалення трійок у графі; виконання довільного SQL/Python коду; видача відповідей без підтвердженого джерела (doc_id).
* Human-in-the-Loop (HITL): усі пропозиції нових фактів проходять через propose_fact із ручним підтвердженням для середнього та високого ризику.

## 4. Архітектура памʼяті агента
* Короткострокова (робоча памʼять стану графа): зберігає поточний запит, історію викликів інструментів та знайдені цитати в межах сесії (TTL = 30 хвилин).
* Довгострокова (верифікована база знань): зберігає затверджені факти з prov:wasDerivedFrom у data/hub.ttl (TTL = безстроково).
