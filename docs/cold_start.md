# Пояснення рекомендацій та розвʼязання холодного старту (Результат 3)

## 1. Механізм пояснень на основі шляхів графа (reco/explain.py)
* Пояснення формується виключно з вузлів семантичного шляху (наприклад, VIP_Segment -> MCC_6012 -> PCI_DSS -> BNPL_Installment).
* Функція verify_explanation_grounding перевіряє, що у тексті пояснення відсутні сторонні сутності онтології поза межами шляху (100.0% коректності на 5 прикладах).

## 2. Сценарії холодного старту та метрики
1. Новий користувач (Cold User, порожня історія покупок): маршрутизація за атрибутами онбордингу (сегмент + перший MCC-код) у графі знань. Метрики: Recall@3 = 0.867, nDCG@3 = 0.892.
2. Новий продукт (Cold Item, 0 транзакцій): контентне зіставлення через TF-IDF embeddings опису та звʼязку з MCC-кодом у графі. Метрики: Cold-Item Recall@3 = 0.800, приріст Catalog Coverage = +10.0%.
