# Звіт після очищення сховища та вплив на RAG (Результат 5)

## 1. Вплив очищення на метрики RAG (3 ключові висновки)
1. **Дедуплікація (`Uniqueness` +22.2%) підвищила `Context Recall` на +0.166:** об'єднання синонімічних вузлів (`BNPL_Installment` та `Оплата частинами BNPL`) усунуло фрагментацію графа при побудові підграфа для RAG.
2. **Розв'язання суперечностей значень та класів (`Consistency` +16.7%) підвищило `Faithfulness` на +0.155:** видалення застарілих лімітів (`50000` проти `75000`) та конфліктуючих сегментів (`VIP` + `Subprime`) припинило генерацію суперечливих відповідей LLM.
3. **Заповнення походження (`Provenance` +16.7%) підняло `Abstention Accuracy` до 1.000 (+0.250):** система тепер коректно відхиляє запити щодо непідтверджених сутностей без джерела.

## 2. Процес підтримки якості сховища знань (Data Governance)
* **Власники:** Інженер знань (`Лоскутова А. А.`) — схема SHACL, дедуплікація та CI; Доменний експерт — верифікація фінансових лімітів і MCC-кодів.
* **Періодичність переглядів:** автоматична перевірка у GitHub Actions при кожному `push`/`PR`; плановий аудит актуальності (`updatedAt`) — щомісяця.
* **Пороги та алерти:** блокування злиття (CI Gate fail) при `SHACL Validity < 100%`, `Consistency < 100%`, `Provenance < 95%` або `Uniqueness < 98%`.
