# Безпека агента та результати Red Teaming (Результат 4)

## 1. Порівняння результатів «до» та «після» впровадження захистів
* До захисту (базовий виклик без фільтрації): заблоковано 16.7% атак (1/6).
* Після впровадження захистів (agent/graph_agent.py, mcp_server/server.py): заблоковано 100.0% атак (6/6).

## 2. Реалізовані механізми захисту в коді
1. Вхідний Guardrail та санітизація непрямих інʼєкцій (agent/graph_agent.py: _sanitize_untrusted_text) — нейтралізує інструкції перехоплення керування у запитах і текстах документів.
2. Примусовий Read-Only режим (mcp_server/server.py: file:data/olap.db?mode=ro та білий список SELECT-шаблонів) — блокує будь-які спроби зміни чи видалення даних.
3. Обмеження кроків та довжини входу (max_steps = 5, зрізання параметрів [:64]) — захищає від зациклення та виснаження бюджету токенів.

## 3. Залишкові ризики (3 ризики)
1. Семантично замасковані багатоходові інʼєкції (Multi-turn jailbreaks), які не містять явних стоп-слів.
2. Потенційний витік агрегованої бізнес-статистики через серію легітимних вузьких запитів до OLAP-вітрини.
3. Застарівання зовнішніх документів у data/docs.json між плановими щомісячними аудитами графа.
